# Demo 使用与验证

实现日期：2026-10-18。

> 本文保留已验收 demo 的历史范围及环境记录。1.0.0 已完善增量路径扫描、配置恢复和自包含发布；当前行为以 [使用说明](user-guide.md) 和 [交付验证](release-validation.md) 为准。

## 运行

在 Visual Studio 中打开 `HardLinkAutoBackup.slnx`，按 F5 运行。已编译的 Release 程序位于 `bin/Release/net10.0-windows/HardLinkAutoBackup.exe`；该 demo 使用本机已有的 .NET 10 Windows Desktop Runtime，移动程序时需要保留同目录的 DLL 和配置文件。独立运行、内置运行时的发布包留待正式发布时生成。

首次启动没有示例任务。点击“新建任务”选择实际目录；保存已启用任务后会自动首次扫描。暂不想扫描时，关闭任务或全局自动开关。完整扫描周期为 10 秒到 365 天，文件事件还会在约 2 秒静默后触发扫描。自动开关关闭时手动扫描仍可用，正在执行的扫描可用“取消扫描”停止。

默认关闭窗口后驻留通知区域。双击托盘图标打开界面；需要完全停止时从托盘菜单退出。默认不开启开机自启和管理员启动。设置中开启自启时会明确展示计划任务名称、程序路径和撤销办法，再由用户确认和接受 Windows 提权。

## 已实现

- 最多 100 个任务，任务新增、编辑、移除、启用和暂停；最多 2 个任务同时扫描。
- 源文件直接创建 NTFS 硬链接，文件 ID 校验、重复扫描幂等、删除源路径后保留备份。
- 同名异对象和文件/目录类型冲突时另存于 `.hlab-conflicts`，不覆盖旧备份。
- 周期完整扫描、文件事件合并、监控异常后的重建和补扫。
- 相对路径排除；默认跳过重解析点和程序自己的数据目录。
- Unicode 和长路径、同卷校验、规范化实际路径、跨任务嵌套检查。
- 托盘菜单、单实例唤醒、任务状态、扫描详情、最近 500 行日志查看。
- JSON 配置持久化、写入时原子替换及 `.bak` 配置副本、日志轮转。
- 登录自启及提升权限设置的实现；系统操作只在用户确认设置后触发。

主列表的“本次链接”是最近一次扫描确认的链接数量，并非备份目录所有保留文件的数量，也不是实际占用空间。

## 项目内文件

- 程序配置和日志：运行目录的 `data/`。
- 构建产物：`bin/` 和 `obj/`。
- 构建缓存和临时目录：`.local/`。
- 自动测试数据、报告和预览图：`.demo-checks/`。测试使用独立新建目录，仅删改测试自己的文件，保留数据供复核。

这些目录已加入 `.gitignore`。构建脚本将 CLI 主目录、缓存、临时目录限定在项目内，并显式禁用首次初始化的 HTTPS 开发证书生成、全局工具 PATH 配置及遥测。还原只使用项目内空包源和 SDK 已有的目标包，不安装全局组件。

## 重复验证

在项目根目录的 PowerShell 中执行：

```powershell
.\scripts\Build-Demo.ps1
.\scripts\Test-Demo.ps1
```

验证覆盖真实硬链接、幂等扫描、共享写入、源文件删除、同名替换、重命名、排除路径、嵌套拒绝、取消、配置保存、文件转目录、长路径，以及后台首次扫描、文件事件触发、周期补扫、总开关和手动触发。结果保存到 `.demo-checks/latest-results.txt`。界面渲染预览位于 `.demo-checks/preview/`，预览中的任务仅用于展示，不会保存为用户任务或扫描示例路径。

自启注册、UAC 提权、注销后自动启动没有在用户电脑上自动实测，避免未获授权的系统修改。跨卷拒绝逻辑已实现，但测试目录仅使用项目所在卷；跨卷、实际权限拒绝、大规模文件负载和不同 DPI 的系统级验证仍需后续补充。

## 当前限制

- 空目录不创建备份；只为文件建立对应父目录。
- 文件事件在任务级合并后执行完整遍历，目前尚未实现只遍历发生变化的子路径；大量文件目录的响应时间需要后续负载测试。
- 自动开关暂停后，已在执行的扫描继续到完成或用户取消。
- 同名冲突的旧备份保持原位，当前源对象的链接需要到 `.hlab-conflicts` 中查找。
- 从一个管理员账户切换为另一个账户的 UAC 凭据方式暂不支持，以免把登录任务注册到错误的用户。
- 程序目录必须可写。路径不可用时记录错误，任务仍保留，后续扫描可重试。
- 配置文件损坏时保留原文件并停止启动，用户可检查 `settings.json.bak` 后恢复。

## 本次构建环境记录

首次执行构建时，SDK 10.0.401 的初始化输出报告“已安装 ASP.NET Core HTTPS 开发证书”和“未能将项目内的 .NET tools 路径添加到 PATH”。虽然当时已将 CLI 主目录、包缓存和临时目录放在项目内，但未显式禁用开发证书生成及全局工具 PATH 设置。这是超出用户环境边界的意外操作。

2026-10-18，用户明确允许所述只读核查后，执行 `Get-ChildItem Cert:\CurrentUser\My`，仅筛选 Subject 为 `CN=localhost` 且 FriendlyName 为 `ASP.NET Core HTTPS development certificate` 的条目。命令成功完成，未返回匹配条目；没有读取私钥、删除证书或修改信任设置。

该结果仅代表本次命令可见的当前用户个人证书库中没有匹配上述条件的条目，不能据此断言所有证书库均不存在相关证书，也未能确认初次构建输出所指的新增证书。因此没有可供精确清理的指纹，没有执行删除或扩大检查范围。后续构建脚本已设置 `DOTNET_GENERATE_ASPNET_CERTIFICATE=false` 和 `DOTNET_ADD_GLOBAL_TOOLS_TO_PATH=false`。
