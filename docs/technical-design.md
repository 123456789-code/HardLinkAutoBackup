# 技术设计

状态：技术设计基线（2026-10-18）。首版 demo 已实现，运行和验证范围见 demo.md。

## 1. 已确认技术栈

- **语言与框架**：C#、.NET 10、WinForms。现有 `HardLinkAutoBackup.csproj` 已使用 `net10.0-windows`、`UseWindowsForms=true` 和 `WinExe`，保持此基础。
- **进程形式**：一个用户登录后运行的 GUI/托盘进程，后台扫描任务在同一进程中执行；第一版不创建 Windows 服务。
- **硬链接接口**：使用 Windows `CreateHardLinkW`，通过 .NET 平台调用封装，并将 Win32 错误码转为可理解的任务错误。目标路径存在时不调用覆盖操作。
- **文件身份**：使用 Windows 文件句柄查询卷序列号与文件 ID，判断源和备份是否为同一文件对象。时间戳、大小和文件名仅用于显示，不能代替身份判断。
- **监控与调度**：`FileSystemWatcher` 提供及时发现；定期完整扫描补漏。事件处理只入队，不在回调线程遍历目录。使用异步队列、取消令牌和受限并发。
- **配置与日志**：`System.Text.Json` 保存程序设置与任务配置；可读文本或 JSON Lines 日志记录扫描结果与错误，不引入数据库。
- **代码风格**：遵守项目根目录 `.editorconfig` 与 `docs/代码规范.md`；两者冲突时以 `.editorconfig` 为准。其通用设置包括 UTF-8 BOM、CRLF、Tab 缩进和文件末尾换行。不要根据规范示例覆盖 `.editorconfig` 的具体命名或格式规则。

## 2. 建议模块边界

```text
WinForms 主窗体 / 任务编辑窗体 / 设置窗体 / 托盘菜单
                    │
                    ▼
应用控制器：单实例、生命周期、设置与状态通知
                    │
       ┌────────────┴────────────┐
       ▼                         ▼
任务调度器与事件队列          配置和日志存储
       │
       ▼
扫描器：枚举、过滤、路径映射、结果汇总
       │
       ▼
Windows 文件系统适配层：NTFS/卷校验、文件 ID、CreateHardLinkW
```

UI 不直接执行硬链接操作；扫描器也不直接操作窗体控件。这可保证隐藏界面后继续运行，并让文件系统规则可独立测试。第一版可以在同一 WinForms 项目中按目录分层，暂不需要增加多个项目或第三方依赖。

## 3. 数据模型

`AppSettings`：开机自启、管理员权限启动、周期备份总开关、关闭界面后台驻留、配置版本。

`BackupTask`：稳定的任务 ID、显示名称、源目录、备份目录、周期、任务自动开关、排除规则、创建时间。

`TaskRuntimeState`：运行状态、最近扫描开始和结束时间、下次扫描时间、已确认链接数、本次新增数、跳过数、失败数、最近错误。运行状态与用户配置分离，避免频繁扫描时反复改写配置文件。

任务配置写入临时文件后原子替换，读取失败时保留原文件并报告错误；配置版本字段用于将来的迁移。日志按大小或日期轮转，仅清理程序自身的旧日志，不清理用户备份数据。

## 4. 路径校验与扫描算法

创建或编辑任务时：

1. 将路径转为绝对路径并规范化；对重解析点进行识别，防止以联接点绕过嵌套检查。
2. 检查源存在、备份位置可创建、二者位于同一 NTFS 卷。对暂时离线的卷，任务可保存为错误状态，但不能开始扫描。
3. 检查本任务及跨任务的源/备份嵌套关系。一个任务独占自己的备份目录；任务之间共享源目录可以提示重复备份风险。
4. 检查目标目录已有内容；首次运行不得覆盖同名对象。

完整扫描伪流程：

```text
若全局或任务自动开关关闭且非手动触发：结束
若该任务正在扫描：记录一次待扫描请求后结束
枚举源目录（不进入重解析点，应用排除规则）
对每个普通文件：
    计算其相对于源目录的路径
    在备份目录建立对应的父目录
    若目标不存在：尝试 CreateHardLinkW(目标, 源)
    若目标存在且文件 ID 与源相同：记为已备份
    若目标存在但文件 ID 不同：按已确认的冲突规则保存新对象并记录提示
    单项出错：记录错误并继续
汇总结果、更新时间、安排下次周期扫描
```

为避免竞态，创建链接后可重新比较源和目标的文件身份；如果源文件在检查期间被替换，本次结果记为需重试。扫描不修改源文件内容或属性。已经删除的源路径不会驱动任何备份路径删除。Win32 错误应包含操作、相对路径和错误码，便于定位。

## 5. 监控、周期和并发

- 每个启用任务监控其源目录及子目录。文件系统事件经去抖后将相关路径放入队列；目录重命名、监控错误或事件溢出时安排完整扫描。
- 周期以“上次完整扫描结束时间 + 设定间隔”计算，界面展示下次时间。启动或从休眠恢复时进行一次补扫，不为错过的每个周期重复扫描。
- 同一任务最多一个扫描在运行；跨任务使用小规模可配置或固定的并发上限，默认先以 2 个任务并行作为实现起点。任务队列应保证取消、暂停和退出时可收束。
- 进度更新做频率限制，避免大量文件让 UI 线程阻塞。100 个任务是配置容量目标，不代表 100 个扫描同时运行。

## 6. 程序生命周期与开机启动

- 使用 WinForms `ApplicationContext` 管理主窗口与 `NotifyIcon`。窗口隐藏时应用消息循环继续运行；关闭后台驻留开关时销毁托盘图标并退出进程。
- 使用当前用户范围内的单实例机制。第二次启动通知现有实例显示窗口。
- “开机自启”拟通过 Windows 任务计划程序注册**当前用户登录触发器**，指向发布目录中的程序绝对路径；不使用 Windows 服务。管理员开关对应计划任务的提升权限级别。手动启动时若需要提升，由 Windows 提示用户。
- 自启任务只由设置界面的明确操作创建、更新或移除；程序启动时可以读取其状态，但不能悄悄修复、覆盖其他同名任务。关闭自启时仅移除本程序创建的任务。
- 实施前必须向用户列明实际任务名、可执行文件路径、将调用的系统接口或命令、持久影响和撤销办法，并获得针对该操作的明确确认。当前文档和后续纯代码开发均不等于获准修改本机计划任务、用户配置或安装组件。

## 7. 配置、发布与环境整洁

- 优先发布为 **win-x64 自包含文件夹**：运行端不需要额外安装 .NET；文件放在用户选定的单一程序目录，不制作安装器、不写入 PATH、不安装服务。
- 拟在该程序目录的 `data` 子目录保存配置与日志，便于完整迁移或移除。程序目录需可写；若用户选择受保护位置，必须另行商定配置位置，而不是未经确认写入项目外的用户目录。
- 发布目录搬动后，登录自启所保存的绝对路径会失效。UI 启动时检查并提示，只有用户明确操作时才更新计划任务。
- 开发所需 SDK、Visual Studio 工作负载和其他组件是否已有，实施时仅做项目内开发；不擅自安装、卸载或改动全局环境。

## 8. 测试策略

使用项目内或用户明确指定的临时 NTFS 测试目录验证，不拿真实数据目录做破坏性测试。至少覆盖：

1. 新文件建链后，源/备份文件 ID 相同；源路径删除后备份可读。
2. 原地修改在两处同步可见，文案准确提示局限。
3. 文件重命名、目录重命名、源路径被新文件对象替换时不覆盖旧备份。
4. 非 NTFS、跨卷、路径嵌套、目标同名异对象、权限不足、文件占用、长路径及 Unicode 文件名。
5. 大量文件事件、监控溢出、程序中断、休眠恢复后的完整扫描补漏。
6. 任务和全局开关、托盘隐藏与退出、重复启动、配置损坏后的错误提示。

自启与管理员权限的端到端测试会改动系统计划任务，须在取得用户对该具体操作的确认后再做。
